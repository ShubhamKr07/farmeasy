# Supabase Auth Migration (Clerk → Supabase Auth) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace Clerk with Supabase Auth as the identity provider across all three apps (`api-server`, `admin-dashboard`, `farmeasy`), with existing users transitioned via forced password reset, and a real `users` table replacing free-text Clerk ID columns — with zero loss of the app-specific `role` claim existing code depends on.

**Architecture:** Supabase Auth (already provisioned — same Supabase project as the DB migration) replaces Clerk end to end: `@clerk/express` middleware → Supabase JWT verification in `api-server`; `@clerk/clerk-react` → `@supabase/supabase-js` in `admin-dashboard`; `@clerk/expo` → `@supabase/supabase-js` in `farmeasy`. A new `users` table (PK = Supabase Auth's `auth.users.id` UUID) replaces every free-text `clerk_user_id`/`created_by` column, populated via a Custom Access Token Hook so `role` still rides in the JWT the way Clerk's `publicMetadata.role` did — no new API round-trip for role lookups. Existing users are pre-created in Supabase Auth by email and sent a password-reset email at cutover (Clerk never exposes password hashes, so there's no silent carry-over).

**Tech Stack:** `@supabase/supabase-js` (web + API verification), `@supabase/supabase-js` for Expo (mobile — Supabase's JS client works in React Native with an AsyncStorage-backed adapter, no separate Expo-specific package), Supabase Auth (email/password + Google OAuth + Custom Access Token Hook), Drizzle ORM (existing), Clerk Backend API (`@clerk/backend`, read-only, for the one-time user export).

## Global Constraints

- pnpm only, `pnpm run typecheck` must pass before merge (same as the DB migration plan).
- This plan does **not** touch Storage (`media.ts`'s local-disk uploads) — that's Plan 3.
- The existing Supabase project (`meorgbbtxlpzxyfxmnyu`, `us-west-2`) is reused — no new project.
- `created_by`/`clerk_user_id` columns are renamed to `user_id` (`uuid`, FK to `users.id`) everywhere they appear — no column keeps a `clerk_`-prefixed name after this plan.
- Existing users get a **forced password reset** at cutover (confirmed decision) — no attempt to carry Clerk password hashes, because Clerk does not expose them to anyone, including the account owner.
- `role` must still be readable from the client session with no extra API call after cutover, matching today's `useUserRole()` behavior — implemented via a Supabase Custom Access Token Hook reading `users.role`, not a client-side API fetch.
- The Replit-era `clerkProxyMiddleware.ts` and its mount point are deleted outright, not adapted — Supabase Auth has no equivalent proxy requirement, and the comment in that file ("no external Clerk dashboard... Auth pane") confirms it was Replit-specific tooling that survived the move to Render as dead weight.

Create `supabase/migrations/00XX_custom_access_token_hook.sql` (replace `00XX` with the next sequential number under `supabase/migrations/`):

```sql
create or replace function public.custom_access_token_hook(event jsonb)
returns jsonb
language plpgsql
stable
as $$
declare
  claims jsonb;
  user_role public.user_role;
begin
  select role into user_role from public.users where id = (event->>'user_id')::uuid;

  claims := event->'claims';

  if user_role is not null then
    claims := jsonb_set(claims, '{user_role}', to_jsonb(user_role));
  else
    claims := jsonb_set(claims, '{user_role}', '"technician"');
  end if;

  event := jsonb_set(event, '{claims}', claims);
  return event;
end;
$$;

grant execute on function public.custom_access_token_hook to supabase_auth_admin;

revoke execute on function public.custom_access_token_hook from authenticated, anon, public;
```

**Rationale for the `stable`, restrictive grants**: Supabase's own docs require the hook function to be callable only by `supabase_auth_admin` — granting `execute` more broadly is a real privilege-escalation surface (any authenticated user could otherwise attempt to call the hook function directly).

Create `artifacts/api-server/scripts/export-clerk-users.ts`:

```typescript
import { createClerkClient } from "@clerk/backend";
import { createClient } from "@supabase/supabase-js";
import { writeFileSync } from "node:fs";

const clerk = createClerkClient({ secretKey: process.env.CLERK_SECRET_KEY! });
const supabase = createClient(
  process.env.SUPABASE_URL!,
  process.env.SUPABASE_SERVICE_ROLE_KEY!,
);

type MappingEntry = {
  clerkUserId: string;
  email: string;
  role: string;
  supabaseUserId: string;
};

async function main() {
  const mapping: MappingEntry[] = [];
  let offset = 0;
  const limit = 100;

  while (true) {
    const page = await clerk.users.getUserList({ limit, offset });
    if (page.data.length === 0) break;

    for (const clerkUser of page.data) {
      const email = clerkUser.emailAddresses[0]?.emailAddress;
      if (!email) {
        console.error(`Skipping Clerk user ${clerkUser.id} — no email address`);
        continue;
      }
      const role = (clerkUser.publicMetadata?.role as string) ?? "technician";

      const { data, error } = await supabase.auth.admin.createUser({
        email,
        email_confirm: false, // false so Supabase requires the reset flow, not an auto-confirmed session
      });
      if (error) {
        console.error(`Failed to create Supabase user for ${email}:`, error.message);
        continue;
      }

      await supabase.from("users").insert({
        id: data.user.id,
        email,
        role,
      });

      mapping.push({
        clerkUserId: clerkUser.id,
        email,
        role,
        supabaseUserId: data.user.id,
      });

      const { error: resetError } = await supabase.auth.resetPasswordForEmail(email);
      if (resetError) {
        console.error(`Failed to send reset email to ${email}:`, resetError.message);
      }
    }

    offset += limit;
  }

  writeFileSync("clerk-user-mapping.json", JSON.stringify(mapping, null, 2));
  console.log(`✓ exported ${mapping.length} users, mapping written to clerk-user-mapping.json`);
}

main();
```

```typescript
type MappingEntry = { clerkUserId: string; supabaseUserId: string };
```

- [ ] **Step 2: Write the verification middleware**

Create `artifacts/api-server/src/middlewares/supabaseAuth.ts`:

```typescript
import type { Request, Response, NextFunction } from "express";
import { createClient } from "@supabase/supabase-js";
import { jwtVerify, createRemoteJWKSet } from "jose";

const SUPABASE_URL = process.env.SUPABASE_URL!;
const JWKS = createRemoteJWKSet(
  new URL(`${SUPABASE_URL}/auth/v1/.well-known/jwks.json`),
);

export const supabaseAdmin = createClient(
  SUPABASE_URL,
  process.env.SUPABASE_SERVICE_ROLE_KEY!,
);

declare global {
  // eslint-disable-next-line @typescript-eslint/no-namespace
  namespace Express {
    interface Request {
      supabaseUser?: { sub: string; user_role?: string };
    }
  }
}

export async function supabaseAuthMiddleware(
  req: Request,
  _res: Response,
  next: NextFunction,
) {
  const header = req.headers.authorization;
  if (!header?.startsWith("Bearer ")) {
    return next();
  }
  const token = header.slice("Bearer ".length);
  try {
    const { payload } = await jwtVerify(token, JWKS, {
      issuer: `${SUPABASE_URL}/auth/v1`,
    });
    req.supabaseUser = {
      sub: payload.sub!,
      user_role: (payload as Record<string, unknown>).user_role as string | undefined,
    };
  } catch {
    // Invalid/expired token — leave req.supabaseUser unset, requireSignedIn
    // (app.ts) is what actually rejects the request; this middleware only
    // populates identity, mirroring clerkMiddleware()'s own non-throwing
    // "attach if present, let the route decide" behavior.
  }
  next();
}
```
